# طابوني برو VIP — على Supabase

تطبيق واحد فيه صفحتين:

| مين بيدخل | بشو | شو بيشوف |
|---|---|---|
| **الإدارة** (إنت) | الإيميل + كلمة السر + كود من التلفون | لوحة الإدارة كاملة |
| **الزبون** | رقم التلفون + كلمة السر | بطاقة الطبعات تبعه بس |

**ما في روابط بطاقة.** الزبون بيشوف بطاقته بس لما يدخل بحسابه:
- **عنده طلب من اليوم:** أول ما يدخل بيطلعله التقييم. بيقيّم والطبعات بتنضاف قدّامه.
- **ما عنده طلب:** البطاقة طوالي.

كيف بيصير عنده "طلب من اليوم"؟ بلوحة الإدارة ← **سجّل الطلب** (اسم الزبون + عدد البيتسا).
- **التقييم صالح لنفس اليوم بس** (لحد منتصف الليل بتوقيت البلاد)، ولمرة وحدة.
- زر واتساب للتذكير (اختياري)، والرسالة فيها رابط التطبيق بس.
- **زبون بدون حساب:** بيوصله رابط تقييم لمرة وحدة (`?t=`) كاحتياط. الأحسن تعمله حساب.
- روابط بطاقة قديمة (`?c=`) بتفتح شاشة الدخول.
- `?new=1` صفحة الانضمام.

```
 المتصفح (GitHub Pages)                    Supabase
┌──────────────────────┐   RPC + JWT   ┌────────────────────────────────────────┐
│ index.html + js      │ ────────────▶ │ public: دوال بس (كل دالة بتفحص الدور)   │
│ supabase-js (anon)   │               │ app:    الجداول (مخفية + RLS)          │
└──────────────────────┘               │ Auth:   كلمات السر (bcrypt)            │
          │ إدارة بس                    │ Edge Function admin-users (مفتاح سري) │
          └───────────────────────────▶ └────────────────────────────────────────┘
```

## التركيب، خطوة خطوة

### 1) مشروع Supabase
1. ادخل على **supabase.com ← New project**.
2. **Region:** اختار **Central EU (Frankfurt)**، لأنه الأقرب لإسرائيل.
3. احفظ **Database password** بمكان آمن.

### 2) إعدادات الدخول (مهم للحماية: كل سطر)
**Authentication ← Sign In / Providers** و **Authentication ← Settings / Policies**:

| الإعداد | القيمة | ليش |
|---|---|---|
| **Allow new users to sign up** | ❌ **مطفي** | ما حدا بيقدر يفتح حساب لحاله. بس إنت من الإدارة |
| **Allow anonymous sign-ins** | ❌ مطفي | |
| **Email provider** | ✅ مشغّل | الدخول بالإيميل/كلمة السر |
| **Phone / Magic link / OAuth (Google…)** | ❌ كلهم مطفيين | طرق دخول ما بنستعملها = أبواب زيادة |
| **Confirm email** | ✅ مشغّل | حسابات الزبائن بتنعمل مؤكدة من السيرفر، فما بيأثر عليهم |
| **Secure email change** | ✅ مشغّل | ما حدا بيقدر يغيّر إيميل حسابه بدون تأكيد |
| **Secure password change** | ✅ مشغّل | تغيير كلمة السر بيطلب دخول جديد. التطبيق بيعمل هاد لحاله |
| **Minimum password length** | **8** أو أكثر | السيرفر بيرفض أقصر، حتى لو حدا تخطّى التطبيق |
| **Password requirements** | **Letters and digits** | كمان بالسيرفر، مش بس بالتطبيق |
| **Leaked password protection** | ✅ (إذا متوفر بخطتك) | بيمنع كلمات سر مسرّبة بالإنترنت |
| **Multi-Factor (TOTP)** | ✅ مشغّل | للإدارة (خطوة 4) |
| **JWT expiry** | 3600 (ساعة) | الافتراضي، ما تكبّره |
| **Refresh token reuse detection** | ✅ مشغّل | جلسة مسروقة بتنقفل |

**Project Settings ← Data API ← Exposed schemas:** `public` **بس**. أبداً ما تضيف `app` أو `net`.

**Authentication ← URL Configuration ← Site URL:** رابط التطبيق (خطوة 6).

### 3) الداتابيس
**SQL Editor ← New query**. الصق كل ملف وشغّله (**Run**)، **بالترتيب**:
1. `supabase/01_schema.sql`: الجداول والحماية.
2. `supabase/02_api.sql`: الدوال والصلاحيات.

> كل ملف بيشتغل كمعاملة وحدة: إذا صار خطأ، ولا إشي بيتطبّق.

### 4) حساب الإدارة
1. **Authentication ← Users ← Add user ← Create new user**:
   - **Email:** `ayman@staff.tabooni.invalid` ← بالتطبيق بتدخل باسم المستخدم **`ayman`** بس.
     (اسم مستخدم غيره؟ `اسمك@staff.tabooni.invalid`. أو إيميل حقيقي، وبتدخل فيه كامل.)
   - كلمة سر قوية (12 خانة أو أكثر). ✅ **Auto Confirm User**.
2. **SQL Editor:** شغّل هالسطر (بنفس الإيميل):
   ```sql
   insert into app.staff(user_id) select id from auth.users where email = 'ayman@staff.tabooni.invalid';
   ```
   > نسيت كلمة السر؟ **Authentication ← Users ←** الحساب **← Delete user**، واعمله من جديد مع السطر فوق.
3. **التحقق بخطوتين (إجباري للإدارة):** نزّل على تلفونك **Google Authenticator** أو **Microsoft Authenticator**.
   - بأول دخول للتطبيق بالإيميل، بيطلعلك QR. امسحه بالتطبيق، واكتب الكود (6 أرقام).
   - من بعدها كل دخول = كلمة السر + الكود. حتى لو حدا عرف كلمة السر، ما بيقدر يدخل بدون تلفونك.
   - **ضيّعت التلفون؟** من Supabase: **Authentication ← Users ←** حسابك **← MFA factors ← Delete**. بالدخول الجاي بتعمل QR جديد.

### 5) الـ Edge Function: حسابات دخول الزبائن
**Edge Functions ← Deploy a new function ← Via Editor**:
1. الاسم بالظبط: `admin-users`.
2. الصق محتوى `supabase/functions/admin-users/index.ts` ← **Deploy**.
3. **Settings ← Verify JWT with legacy secret:** ❌ **مطفي** (زي ما Supabase بينصح). الدالة بتفحص بنفسها: جلسة حقيقية + إدارة + كود من التلفون + من موقعك بس.
4. **Edge Functions ← Secrets ← Add:**
   - `ALLOWED_ORIGINS` = رابط التطبيق بدون `/` بالآخر: `https://app.taboonipro.com`. **إجباري**: بدونه الدالة بترفض كل طلب.

> المفتاح السري (service_role) Supabase بيعطيه للدالة لحاله. **أبداً ما تحطه بالتطبيق ولا بـ GitHub.**

### 6) التطبيق على GitHub Pages
1. ارفع كل الملفات اللي **برّا** مجلد `supabase/` لجذر الريبو (index.html و js و css و assets…)، بدل الملفات القديمة.
2. افتح `config.js` وعبّي:
   - `SUPABASE_URL`: من **Project Settings ← Data API ← Project URL**.
   - `SUPABASE_ANON_KEY`: من **Project Settings ← API Keys ← anon / publishable**.
3. **Settings ← Pages ← Deploy from branch ← main / root**.
4. **الدومين: `app.taboonipro.com`** (موقع Shopify على `taboonipro.com` بيضل مثل ما هو).
   > ليش مش `xxx.github.io`؟ لأنه مشترك بين كل مواقع حسابك على GitHub. أي ريبو ثاني على نفس الحساب بيقدر يقرأ جلسة الزبائن.

   **أ) بـ Shopify (لأنه الدومين هناك):** **Settings ← Domains ←** `taboonipro.com` **← Domain settings ← Edit DNS settings ← Add custom record**:
   | Type | Name | Points to |
   |---|---|---|
   | `CNAME` | `app` | `USERNAME.github.io` (اسم حسابك على GitHub) |
   - ما تلمس سجلات `@` و `www`، هدول تبع Shopify.
   - إذا الدومين مش مشتري من Shopify، نفس السجل بتضيفه عند الشركة اللي اشتريته منها.

   **ب) بـ GitHub:**
   1. **Settings ← Pages ← Custom domain:** `app.taboonipro.com` ← **Save**.
   2. استنى لحد ما يطلع ✅ "DNS check successful". بياخذ من دقائق لكم ساعة.
   3. شغّل ✅ **Enforce HTTPS**.
   - (ملف `CNAME` بيعمله GitHub لحاله لما تحط الدومين.)

   **ج) بعدها حدّث:**
   - Supabase ← **Authentication ← URL Configuration ← Site URL** = `https://app.taboonipro.com`.
   - Edge Function secret `ALLOWED_ORIGINS` = `https://app.taboonipro.com`.
   - بإعدادات التطبيق ← **رابط التطبيق** (إذا موجود) = `https://app.taboonipro.com/`.

   **د) اختياري:** بـ Shopify، زر أو رابط بالقائمة: **"بطاقة VIP"** ← `https://app.taboonipro.com`.

### 7) نقل البيانات من Google Sheets (مرة وحدة)
1. شغّل `supabase/04_import_tables.sql`.
2. بالشيت **Tabooni Stamps**، نزّل كل ورقة كـ CSV (**File ← Download ← CSV**): Customers, Tokens, Feedback, Rewards, Settings.
3. **Table Editor**:
   1. افتح `import_customers` ← **Insert ← Import data from CSV** ← اختار `Customers.csv`.
   2. اعمل نفس الإشي لكل جدول مع الملف تبعه.
4. شغّل `supabase/05_migrate.sql`. بالآخر بيطلعلك ملخص، مثلاً: `customers=84, rewards=12, …`.

ملاحظات:
- **الطبعات والهدايا بتنتقل كاملة.** روابط البطاقة القديمة (`?c=`) بتفتح شاشة الدخول.
  - رقم بطاقة قصير (أقل من 16 خانة) بياخذ رقم داخلي جديد (`short_ids_rotated` بالملخص). ما بيأثر على الزبون.
- روابط التقييم المفتوحة (`?t=`) بتنتقل كمان.
- كلمات سر الزبائن القديمة ما بتنتقل، لأن Supabase بيشفّر بطريقة غير. بتعطيهم جديدة من الإدارة (خطوة 9).

### 8) فحص الأمان
شغّل `supabase/06_security_check.sql`. **كل الأسطر لازم تطلع ✅.** إذا في ❌، ما تكمل وخبّرني.

### 9) اشتراك الزبائن (لحالهم)
- **رابط للمجموعة:** `https://taboonipro.github.io/TabooniPRO/?new=1` (أو زر "اشترك" بشاشة الدخول).
- الزبون بيعبّي اسمه ورقمه وبيختار كلمة سر ← بيشوف بطاقته طوالي.
- بالإدارة ← **تسجيلات جديدة** ← ✓ موافقة (أو ✕ رفض). تسجيل طلب للزبون بيوافق لحاله.
- **رقم كان إله بطاقة:** ما بيشوف البطاقة القديمة لحد ما توافق. تأكد إنه صاحب الرقم.
- **حماية:** 5 تسجيلات بالساعة لكل جهاز، 3 باليوم لكل رقم، وإذا صار في 200 تسجيل بيستنوا موافقة التسجيل بيتسكّر لحاله (هجوم) وبيطلع تنبيه بـ `app.audit_log` (`signup_flood`).
  - تنظيف بعد هجوم: ارفض التسجيلات من التبويب، أو:
    `delete from app.customers where source = 'app' and approved_at is null and total_stamps = 0 and signup_at > now() - interval '1 day';` (وبعدها احذف حساباتهم من Authentication ← Users).

### 9ب) إعطاء زبون دخول (من الإدارة)
بالتطبيق ← **الزبائن** ← الزبون ← **⋯** ← **كلمة سر للدخول**:
- بتطلع كلمة سر مؤقتة **مرة وحدة**، وزر يبعثها على واتساب.
- بأول دخول الزبون لازم يختار كلمة سر خاصة فيه، 8 خانات أو أكثر.
- صلاحية كلمة السر المؤقتة أسبوع.
- **كلمة سر جديدة:** الحساب القديم بينحذف، وكل أجهزته بتطلع فوراً.
- **إيقاف الدخول:** الحساب بينحذف، والبطاقة والطبعات بتضل.
- **زبائن قدام:** أعطي كل الزبائن حسابات (زر **كلمة سر للدخول** مباشرة جنب الزبون اللي ما عنده حساب)، عشان تقييماتهم تكون بالتطبيق.

### 10) (اختياري) إيميل لما يجي تقييم منخفض
1. **Database ← Extensions:** فعّل `pg_net`.
2. اعمل حساب مجاني على **resend.com** ← **API Keys**.
3. انشر Edge Function اسمها `notify` من `supabase/functions/notify/index.ts`، و**Verify JWT** ❌ مطفي.
4. **Secrets:**
   - `NOTIFY_SECRET`: نص عشوائي، **32 خانة أو أكثر** (أقصر أو نص المثال = ما بينبعث إيميل).
   - `RESEND_API_KEY`: المفتاح من Resend.
   - `ALERT_EMAIL`: إيميلك.
5. افتح `supabase/03_notify.sql`، وحط رابط الدالة ونفس `NOTIFY_SECRET`، وشغّله.

### 11) المشروع القديم (Google Apps Script)
- **مشروع الزبون (Tabooni Public):** خليه شغّال. بيحوّل الروابط القديمة للتطبيق الجديد، بشرط إنه رابط التطبيق محفوظ بإعداداته (`PUBLIC_URL` بورقة Settings بالشيت).
- **مشروع الإدارة القديم:** ما عاد تستعمله. **Deploy ← Manage deployments ← Archive**، واحذف الـ Trigger تبع النسخة الاحتياطية.
- **الشيت:** خليه كنسخة احتياطية للبيانات القديمة، بس ما عاد بيتحدّث.

## الحماية: شو عملنا

| الطبقة | كيف |
|---|---|
| **الجداول** | بمخطط `app` المخفي عن الـ API، وفوقه RLS بدون سياسات. حتى مع المفتاح العام ما في وصول مباشر |
| **الدوال** | `security definer` + `search_path` ثابت. كل دالة بتفحص الدور بأول سطر. الصلاحيات بالاسم: للزوار 4 دوال بس |
| **كلمات السر** | Supabase Auth (bcrypt). ولا كلمة سر بجداولنا |
| **حسابات الزبائن** | بتنعمل وبتنحذف بس من Edge Function بالمفتاح السري، وبعد فحص إنه الطالب إدارة. التسجيل الذاتي مقفول |
| **إيميلات الزبائن** | داخلية: `رقم@tabooni.invalid`. الدومين محجوز عالمياً، فما حدا بيقدر يستلم عليه "نسيت كلمة السر" |
| **رقم غير مؤكد** | صفحة الانضمام ما بتعطي رابط بطاقة، وبترد نفس الرد لأي رقم (ما بتكشف مين زبون). لما يتأكد الرقم (رابط واتساب، طبعة أو كلمة سر من الإدارة)، رابط البطاقة بيتغيّر |
| **الإدارة** | كلمة سر + كود من تطبيق المصادقة (MFA). السيرفر نفسه بيرفض أي جلسة إدارة بدون الخطوة الثانية |
| **كلمة السر المؤقتة** | السيرفر بيتأكد بنفسه إنه الزبون غيّرها فعلاً (مش المتصفح) |
| **حسابات الإدارة** | ولا عملية بتقدر تحذف حساب إدارة. في حماية بالداتابيس |
| **حدود الاستعمال** | لكل IP (من Cloudflare بس، ما بينزوّر؛ IPv6 بالـ /64) ولكل رقم ولكل رابط. العدّاد ما بينلغي لو الطلب فشل. هجوم تسجيلات = تنبيه بسجل الرقابة، بدون ما يوقف الزبائن الحقيقيين |
| **جلسة الإدارة** | بتنمسح لما تسكّر الصفحة، وبتطلع تلقائياً بعد 30 دقيقة بدون استعمال |
| **التركيب** | كل ملف SQL معاملة وحدة: ما في نص-تركيب يترك إشي مفتوح |
| **المتصفح** | CSP بيمنع أي سكربت غريب، ومنع تضمين بإطار (clickjacking)، ومكتبة supabase-js محلية (مش CDN) |

**المفاتيح:**
- **anon / publishable:** عادي يكون بالتطبيق، لأنه ما بيفتح إشي.
- **service_role / secret:** ممنوع يطلع من Supabase.
- **Database password:** إلك بس.

## تحديث نسخة (مثلاً v1.0 ← v1.1)
1. **SQL Editor:** شغّل `01_schema.sql` من جديد، بعدين `02_api.sql`. الملفات آمنة للتشغيل أكثر من مرة: ما بتمسح بيانات.
2. **Edge Functions ← admin-users ← Code:** الصق `index.ts` الجديد ← **Deploy**.
3. **GitHub:** ارفع كل الملفات ما عدا `CNAME`.
4. شغّل `06_security_check.sql` ← كله ✅.

## نصائح صيانة
- **التحقق بخطوتين (MFA):** شغّله على حساب Supabase تبعك (**Account ← Security**) وعلى حساب GitHub.
- **النسخ الاحتياطي:** الخطة المجانية ما فيها نسخ احتياطية يومية (Pro: 7 أيام). مرة بالأسبوع: **Table Editor** ← اختار schema `app` ← كل جدول ← **Export to CSV**.
- **الخطة المجانية** بتتوقف بعد أسبوع بدون أي استعمال. مع زبائن يوميين هاد مش رح يصير.
- **بعد أي تعديل SQL:** شغّل `06_security_check.sql`.
- **أي دالة جديدة:** لازم تكون `security definer`، وتفحص `app.is_admin()` إذا هي للإدارة، وتنعطى صلاحية بالاسم بس. (الدوال الجديدة مقفولة تلقائياً.)
- **مرة بالشهر:** **Advisors ← Security Advisor** بـ Supabase، و `06_security_check.sql`.
- **سجل الرقابة:** `select * from app.audit_log order by id desc limit 50;` (دخول، كلمات سر، حذف، `join_flood`).
